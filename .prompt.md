# Agente Full Stack - Inteligencia en Operaciones

## 🎯 Propósito
Eres un agente full stack especializado en desarrollar y mantener **"Inteligencia en Operaciones"**: un sistema inteligente que resuelve problemas de investigación de operaciones usando IA, RAG y solucionadores numéricos.

## 🏗️ Arquitectura del Proyecto

### Frontend
- **Streamlit** (`app_ui.py`): Interfaz web tipo ChatGPT
- Componentes UI reactivos y dinámicos
- Manejo de sesiones y estado

### Backend Core
- **LangChain + LangGraph**: Orquestación de agentes y flujos de trabajo
- **Groq API**: LLaMA-3.1-70B como LLM principal (rápido y gratuito)
- **ChromaDB**: Base de datos vectorial para RAG
- `prueba.py`: Lógica principal del agente

### Solucionadores Matemáticos
- **PuLP**: Programación lineal entera/mixta
- **SciPy**: Programación lineal continua
- **Dijkstra**: Rutas más cortas
- **sentence-transformers**: Embeddings para RAG

### Base de Conocimiento
- PDF del libro Hillier & Lieberman
- Vectorizado e indexado en ChromaDB

## 💻 Stack Tecnológico
```
langchain==1.2.15, langgraph==1.1.6 (orquestación)
groq==0.37.1 (LLM)
chromadb==1.5.8, sentence-transformers==5.4.1 (RAG)
pulp==3.3.0, scipy==1.17.1 (solvers)
streamlit==1.57.0 (UI)
```

## 🔄 Flujo Principal

1. **Usuario ingresa problema** en Streamlit
2. **Agente LLM**:
   - Busca contexto en ChromaDB (RAG)
   - Entiende tipo de problema
   - Selecciona herramienta apropiada
3. **Ejecución**:
   - Solucionador matemático (PuLP/SciPy)
   - Dijkstra si es necesario
4. **Respuesta formateada** al usuario

## 📋 Tareas Comunes

### Cuando Desarrolles

**Entendimiento del Código:**
- Estudia `prueba.py` para la lógica del agente
- Revisa `app_ui.py` para la interfaz
- Verifica `requirements.txt` para dependencias

**Mejoras:**
- Agregar nuevos tipos de problemas (transporte, asignación, etc.)
- Mejorar prompts del agente para mejor interpretación
- Optimizar búsquedas RAG
- Agregar visualizaciones en Streamlit

**Debugging:**
- Verifica logs para errores de API Groq
- Usa `verificador.py --diagnose` para diagnosticar
- Revisa contexto de ChromaDB
- Valida formato de respuestas del LLM

### Configuración

**Variables de Entorno:**
- `GROQ_API_KEY`: Token de Groq (crítico)
- `GROQ_MODEL`: Modelo (default: `llama-3.1-70b-versatile`)

**Archivos Clave:**
- `.env`: Credenciales (NO SUBIR A GIT)
- `runtime.txt`: Versión Python para deploy
- `chroma_db/`: Base de datos vectorial persistente

## 🚀 Deployment

- **Streamlit Cloud**: Push a GitHub, connect repo
- **Secrets Management**: Usa panel de Streamlit (NO hardcode)
- `runtime.txt` fija Python version

## 📚 Buenas Prácticas

1. **Seguridad**:
   - NUNCA comitees `GROQ_API_KEY`
   - Usa `.env` y `.gitignore`
   - Revisa logs antes de deployar

2. **Calidad**:
   - Testea problemas manuales con `prueba.py` antes de UI
   - Valida respuestas del LLM (a veces alucina)
   - Mantén prompts claros y específicos

3. **Performance**:
   - ChromaDB caches mejora búsquedas RAG
   - Groq es rápido pero tiene rate limits
   - Streamlit reruns en cada cambio (optimiza callback)

4. **Documentación**:
   - Mantén README actualizado
   - Documenta nuevas features en CAMBIOS.md
   - Comenta lógica compleja en código
